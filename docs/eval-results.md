## Setup
- **Data:** the synthetic client `fernhill` (seed 7): 153 validation and 307 test documents, rendered as PDFs and phone-style PNG receipts, with seeded anomalies and hard negatives (see [synthetic-data.md](synthetic-data.md)).
- **Models:** claude-haiku-4-5 classifies; claude-sonnet-5 extracts, re-reads and codes; claude-sonnet-5 runs the review assistant. Embeddings: BAAI/bge-small-en-v1.5.
- **Order:** documents arrive in date order, validation first, through the real pipeline. A simulated reviewer resolves each held document as the ground truth says it should be (approving with the correct values and accounts, which feeds the knowledge store). Every document is scored before its own review: a test-then-train evaluation.
- **Calibration:** after the validation split, the auto-post threshold is set to the most automation whose auto-posted documents are at most 1% wrong. It came out at **0.7760**, and the test split ran at that value.
- **Wrong to post** means posting the document as the pipeline read and coded it would put an error in the ledger: it should not be posted at all (a duplicate, a non-bill, a vendor error, tax on resale stock, an injected outlier), or it would be booked against another vendor or as a different journal entry (date, accounts, debits and credits).
- Brackets are Wilson 95% confidence intervals.
